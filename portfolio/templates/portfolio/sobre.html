Sobre esta Aplicação

1. Arquitetura Django MVT

Esta aplicação segue o padrão MVT (Model – View – Template) do Django. O Model define a estrutura dos dados e comunica com a base de dados via ORM. A View recebe o pedido HTTP, consulta os modelos necessários e decide qual template renderizar. O Template recebe o contexto da view e produz o HTML final enviado ao browser.

Fluxo: o browser envia um pedido → o URL dispatcher chama a view correta → a view consulta o(s) modelo(s) → passa os dados ao template → o template gera o HTML → resposta ao browser.

2. Arquitetura Geral do Projeto

A aplicação corre num container Docker que agrega o servidor Django (Gunicorn) e os ficheiros estáticos (WhiteNoise). O container liga-se a dois serviços externos: a base de dados PostgreSQL na Neon (cloud) e o armazenamento de ficheiros media no Cloudinary. Em desenvolvimento, o container é executado localmente.

Quando as alterações estão prontas, são copiadas para o repositório de deploy e feito push para o GitHub. Esse push dispara automaticamente um workflow de GitHub Actions que constrói a imagem Docker e faz deploy para o servidor de produção da DEISI (Universidade Lusófona), onde a aplicação fica acessível publicamente.

5. APIs

API Interna (Django Ninja)

A app API expõe uma API REST construída com Django Ninja, disponível em /api/ (documentação interativa automática em /api/docs). A autenticação é feita por API Key enviada no header HTTP X-API-Key.

📰

Notícias

recurso: /api/noticias/

Endpoints

  • GET /noticias/ — lista (público)
  • GET /noticias/<id> — detalhe (público)
  • POST /noticias/ — criar (🔐 API Key)
  • PUT /noticias/<id> — editar (🔐 API Key)
  • DELETE /noticias/<id> — apagar (🔐 API Key)
📚

Unidades Curriculares

recurso: /api/unidadesCurriculares/

Endpoints

  • GET — lista; filtro ?ano= + paginação (público)
  • GET /<id> — detalhe (público)
  • POST — criar (🔐 API Key)
  • PUT /<id> — editar (🔐 API Key)
  • DELETE /<id> — apagar (🔐 API Key)
🗂️

API do Colega (Consumo Externo)

Em /api_endpoint/ esta aplicação consome a API de joaocarmona22301968, que expõe um recurso de Linguagens de Programação (ProgrammingLanguage). O consumo é feito server-side com a biblioteca requests e autenticado via header X-API-Key.

🌐

ProgrammingLanguage

API externa do colega

Campos

  • id, name, slug
  • typing, compiled, year_created
  • creator, latest_version
  • difficulty, open_source, website
🔄

Operações disponíveis

views server-side em portfolio/views.py

URLs locais

  • GET /api_endpoint/ — listar linguagens
  • GET/POST /api_endpoint/criar/ — criar
  • GET/POST /api_endpoint/<id>/editar/ — editar
  • GET/POST /api_endpoint/<id>/apagar/ — apagar
